Fin Analyzer 面试陈述稿

适用岗位：AI 产品经理 / 金融科技产品岗 预计时长：3-4 分钟（陈述） + 追问

一、开场：一句话讲清楚做了什么（15 秒）

“我做了一个 AI 金融分析工具。输入公司名，自动获取实时数据 + LLM 分析，生成结构化的金融简报。有 CLI 和 Web 两个版本，用的是 DeepSeek API，数据源整合了东方财富实时行情和 Bing 搜索。”

二、问题定义：为什么做这个（30 秒）

"普通投资者想看一家公司，需要同时打开东方财富、巨潮资讯、搜索引擎，信息碎片化严重。大模型能分析、能总结，但它有两个致命问题：幻觉——会编财务数据；时效性——训练数据有截止日期。

我的想法是：用实时数据喂给大模型，让 AI 基于真实数据分析而不是凭空编造。这就是 Fin Analyzer 的出发点。"

三、产品设计：四个关键决策（60 秒）

"产品上我做了几个关键选择：

第一，双界面策略。 CLI 版给技术用户，Web 版给普通投资者——同一个核心引擎，不同界面形态。Web 版用 Streamlit 搭建，Python 原生，零前端代码，三天上线。背后是对用户分层的理解——你不能让普通投资者去敲命令行。

第二，三层数据策略。 这是最核心的设计。第一层用东方财富实时行情 API——免费、无需 Key、国内可用、返回精准财务指标。第二层用 Bing 搜索补充新闻动态。第三层——前两层都挂了，LLM 基于训练知识分析，但报告中明确标注数据来源、给出核实建议。三层同时挂的概率极低，任何一层挂了产品都不崩。

第三，防幻觉设计。 不在模型层解决——那是算法工程师的事。我在产品层解决：system prompt 强制要求每条事实标注来源 URL，搜不到就写’公开信息中暂未查到’。理念是：不让 AI 不犯错——做不到；让用户能验证——做得到。

第四，垃圾数据过滤。 Bing 中文搜索有时候会把’宁德时代’拆成’宁德市’，返回旅游攻略。我做了域名黑名单过滤，网盘、知乎专栏、百度百科这些非财经来源直接丢弃。宁可少给数据，不能喂垃圾。"

四、迭代复盘：从 v0.1 到 v0.2 我学到了什么（40 秒）

"这个项目最有价值的不是做对了什么，而是踩过的坑：

第一版 PRD 里我选了 DuckDuckGo 做搜索引擎——免费、不需要 Key、覆盖新闻研报社区讨论。上线后发现国内 100% 不可用。不是’不稳定’，是 DNS 被墙，完全连不上。

然后我开始测试替代方案。HuggingFace Spaces 部署——打不开。Streamlit Cloud——需要 GitHub，也打不开。Bing 搜索一开始效果不错，但我想继续优化——加英文提示词、改搜索参数——结果搜索质量反而下降了。

三个教训： 一是 PRD 写得再好，不生产环境验证也是白搭——理论推演代替不了实测。 二是过度优化有时候不如保持简单——给 Bing 加了一堆参数和英文提示词，结果搜索质量反而下降。最后回到最朴素的方案，效果最好。 三是可用性比低门槛重要——DuckDuckGo 门槛低，但用不了等于零。现在东方财富 API 同样是免费、无需 Key，但国内可用且数据精准。

这个项目让我理解到，AI 产品经理的核心不是写 prompt，而是做三件事：定义用户问题、设计数据策略、处理不确定性。数据输入质量决定 AI 输出质量，而数据源的规划和降级策略，就是 AI PM 和普通 PM 最大的区别。"

五、收尾总结（20 秒）

“总结一下：我不是用 AI 做了一个工具——我是识别了一个用户问题，然后设计了数据策略来让 AI 更好地解决它。产品设计不只是选对方案，更是规划好’出错时怎么办’。”

六、Demo 演示流程（30 秒）

面试时打开浏览器访问 localhost:8501，按以下顺序展示：

  1. 展示 Web 界面：左侧导航、API 配置区
  2. 输入“比亚迪”，点击开始分析
  3. 等待 10-20 秒，展示生成的报告（四模块结构）
  4. 切换到历史记录页面，展示过往分析
  5. 点击下载按钮，展示报告导出功能

如果面试官问“能公网访问吗”： “目前通过 SSH 隧道部署在公网，但稳定性有限，所以我准备了本地 Demo。下一步计划部署到国内云服务器，DEPLOY.md 已经预留了部署方案。”

七、追问预测 & 回答

Q: 和直接问 ChatGPT 有什么区别？

“ChatGPT 没有实时数据，会凭空编财报数字。Fin Analyzer 两层不同：一是接了东方财富实时行情，二是强制要求每条信息标注来源。用户能看到数据从哪来的，可以自己核实。”

Q: 为什么不用现成的金融数据终端（Wind、同花顺）？

“定位不同。Wind 面向机构分析师，功能复杂、年费几万。我的目标用户是普通投资者，要的是’输入公司名，三秒出结论’的极简体验。”

Q: 搜索成功率不高怎么办？

“所以我设计了三层降级。单数据源不可靠——Bing 分词差、东方财富偶然限流、LLM 训练数据过时——但三层同时失效的概率极低。产品设计不是保证每层都完美，是保证’至少有一层可用’。”

Q: 你在这个项目里具体做了什么？

“我独立完成了产品全流程：需求定义 → PRD 撰写 → 技术方案设计 → Python 编码实现（CLI + Web 两个版本）→ 搜索策略迭代（从 DuckDuckGo 到三层数据策略）→ 上线测试 → 问题修复。还写了五份 AI 产品深度体验报告作为竞品分析。”

Q: 如果给你三个月和两个人，你会怎么做？

“三个月分三步：第一个月接付费搜索 API 和更多金融数据源，彻底解决数据质量问题；第二个月加多公司对比、数据可视化、PDF 导出，把分析深度做上去；第三个月做用户测试和迭代，同时部署到国内服务器。两个人分工：一个后端——数据源接入和维护；一个前端——交互优化和可视化。”

Q: 你怎么衡量这个产品好不好？

“两个维度：功能层——报告生成率（目标 99%，三层降级保证）、数据来源标注率；体验层——从输入到出报告的响应时间（目标 15 秒内）、用户是否还需要额外搜索来核实（目标是报告中已覆盖 80% 想知道的信息）。”
