# fin-analyzer 产品需求文档（PRD）

> 版本：v0.1 | 日期：2026.07 | 作者：Yumm-del

---

## 一、产品背景

### 1.1 痛点

普通投资者面对一只股票时，需要打开 3-5 个网站（财报、新闻、研报、社区讨论）才能拼凑出一个完整的认知。这个过程耗时、碎片化、且容易被单一信息源误导。

### 1.2 机会

大模型（LLM）能理解自然语言、能总结、能结构化输出，但有两个致命问题：**幻觉**（编数据）和**时效性**（训练数据有截止日期）。如果能用实时搜索结合 LLM 分析，既解决时效性又防控幻觉，就形成了一个可用产品。

### 1.3 一句话产品定义

> 输入公司名 → 自动搜索 + LLM 分析 → 结构化简报。一个不编数据、有来源、可检验的 AI 金融分析助手。

## 二、目标用户

### 2.1 用户画像

| 类型 | 描述 | 使用场景 |
|------|------|------|
| 初级投资者 | 有投资需求但没时间做系统研究 | 快速了解一家公司的基本情况 |
| 金融专业学生 | 需要做行业分析作业 | 获取结构化报告作为研究起点 |
| 产品好奇用户 | 想体验「AI 金融分析」这件事 | 随便输入一家公司看看效果 |

### 2.2 非目标用户

- 专业机构投资者（需要实时行情、量化数据，这不是本产品范畴）
- 完全不关心金融的用户（这是工具，不是娱乐产品）

## 三、核心功能

### 3.1 P0：单公司分析（必须做）

用户输入公司名称 → 系统自动搜索 + 分析 → 输出四模块结构化报告。

**四模块模板：**

```
一、公司概况 —— 行业、主营业务、近期大事
二、近期动态 —— 利好/利空/中性表格（含来源+时间）
三、核心风险提示 —— 分级风险（🔴高/🟡中/🟢低）+ 影响分析
四、一句话总结 —— 用普通人能懂的语言概括
```

### 3.2 P1：搜索降级策略

如果实时搜索不可用（网络问题、被墙），自动降级使用 LLM 训练知识完成分析，同时在报告顶部标注：*「以下分析基于 AI 训练知识，可能存在时效性不足的问题。」*

### 3.3 P1：并行搜索

三个维度的搜索同时发起（基本面/动态/风险），不串行等待。耗时约等于最慢的那个搜索，而非三者之和。

### 3.4 P2（下个版本）：多公司对比

输入「比亚迪 vs 宁德时代」→ 横向对比 + 差异分析。

### 3.5 P2（下个版本）：数据可视化

报告附带 PE/PB 走势图、行业对比雷达图等。

## 四、关键设计决策

### 决策 1：为什么搜索走 DuckDuckGo 而非东方财富 API？

- DuckDuckGo 搜索结果包含新闻、研报、社区讨论——**覆盖三种信息源**，而非单一财报数据
- 无需 API Key，降低用户使用门槛
- 缺点：国内网络不稳定 → 因此设计了降级策略

### 决策 2：为什么让 LLM 自由分析而非用代码套模板？

- 每家公司的情况不同——比亚迪的风险在于价格战，茅台的在于政策调控。硬套模板会丢失关键洞察
- 通过 system prompt 划框（角色+约束+模板），让 LLM 在框内自由发挥，同时保证输出结构一致

### 决策 3：为什么输出 Markdown 而非 JSON 或 HTML？

- Markdown 人可读、机可解析、可以直接粘贴到飞书/腾讯文档
- JSON 对普通用户不友好，HTML 需要渲染环境

## 五、防幻觉策略

大模型会自信地编造不存在的财务数据。本产品从产品层面（而非模型层面）做三层防控：

| 层级 | 措施 | 用户可感知 |
|------|------|:--:|
| 第一层 | System prompt 硬约束：「绝不编造数据」 | ❌ 用户看不到 |
| 第二层 | 每条事实必须标注来源（搜索结果 URL）| ✅ 用户看到来源链接 |
| 第三层 | 搜索不到时声明「公开信息中暂未查到」 | ✅ 用户知道信息不完整 |

> 设计理念：不是让 AI「不犯错」（做不到），而是让用户「能验证」——从被动相信变成主动检验。

## 六、成功指标

### 6.1 产品指标

| 指标 | 定义 | v0.1 目标 |
|------|------|:--:|
| 报告完整率 | 四个模块全部生成的报告占比 | ≥ 95% |
| 幻觉发生率 | 报告中出现编造数据的比例 | ≤ 5% |
| 搜索成功率 | 至少一个维度搜索成功的比例 | ≥ 80% |
| 平均响应时间 | 从输入公司名到输出报告 | ≤ 15 秒 |

### 6.2 迭代方向

- v0.2：搜索成功率提升（换数据源、加代理池）
- v0.3：多公司对比 + 数据可视化
- v0.4：Web 前端 + 历史走势图

## 七、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 幻觉导致错误分析 | 用户信任崩塌 | 强制来源标注 + 免责声明 + 用户可见的验证路径 |
| 搜索在国内不可用 | 产品核心链路中断 | 降级到 LLM 知识（时效性打折扣但可用） |
| DeepSeek API 服务不可用 | 产品完全不可用 | 下个版本增加多模型 fallback（通义千问/豆包） |
| 监管风险（AI 生成金融内容）| 合规问题 | 每条报告底部标注「不构成投资建议」 |
