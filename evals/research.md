## 三条路线

- 直接接入完整框架：能力丰富，但增加依赖、评测模型配置与费用管理成本。
- 改造现有项目：复用真实业务接口，加固定资料、契约检查、原始响应和人工复核。本轮选择此路。
- 从零建立评测平台：重复搭建界面、账户和服务，超出当前求职项目需要。

## 调研限制与结构理解

按项目流程尝试克隆 DeepEval；GitHub HTTPS 连接失败，因此未假称本地克隆成功。
通过 GitHub API 核验其 README 与用例、evaluate 模块位置。
它的核心结构是：test case 保存输入、输出及上下文，metric 定义判断规则，evaluate 批量执行并记录结果。
本轮独立实现最小评测模块，保留以后迁移到框架所需的 case_id、版本、来源、原始输出与评分字段。
